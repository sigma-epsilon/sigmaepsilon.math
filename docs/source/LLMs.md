# Using the Library with LLMs

The documentation of `sigmaepsilon.math` is LLM-friendly, so that AI tools like Cursor, Windsurf, GitHub Copilot, ChatGPT and Claude can understand and work with the library. Every page in this documentation has a Markdown equivalent generated by the [sphinx-llm](https://github.com/NVIDIA/sphinx-llm) extension, following the [llms.txt standard](https://llmstxt.org/).

To keep the context of your LLM small, `llms.txt` and `llms-full.txt` only cover the pages that show how to use the library: the {ref}`User Guide <user_guide>` with its examples and the {ref}`API Reference <api_reference>`. The {ref}`Theory Guide <theory_guide>` and the {ref}`development guides <development>` are left out, but their pages are still available one by one as Markdown, see the per-page option below.

There are a number of ways to feed the documentation to an LLM, each suited to a different situation.

## Option 1: The index file (`llms.txt`)

`llms.txt` is a lightweight index listing the usage pages of the documentation with their titles and a short description, plus links to the per-page Markdown files. Use this when:

- You are using an agentic AI tool (Claude Code, Cursor, Windsurf, Copilot) that can fetch URLs and decide which pages to read.
- You want the LLM to always reference the latest published documentation rather than a stale downloaded snapshot.
- Your query is focused enough that the LLM only needs to read a few pages rather than the entire documentation.

Point the tool at the URL of the index (the **Copy the URL of llms.txt** button above puts it on your clipboard):

```text
https://sigmaepsilonmath.readthedocs.io/en/latest/llms.txt
```

The LLM can use the descriptions in the index to identify which pages are relevant, then fetch those individual `.html.md` files.

**Example prompt:**

```text
Read https://sigmaepsilonmath.readthedocs.io/en/latest/llms.txt to get an
overview of the sigmaepsilon.math documentation. Then fetch whichever pages
are relevant and help me find all the minima of the Himmelblau function with
particle swarm optimization.
```

```{note}
As of today, these files cannot be natively leveraged by most LLM frameworks or IDEs. Alternatively, an [MCP server](https://modelcontextprotocol.io/docs/getting-started/intro) can be implemented to properly parse the llms.txt file.
```

## Option 2: Full documentation bundle (`llms-full.txt`)

`llms-full.txt` is the usage pages of the documentation, including the API reference, concatenated into a single Markdown file. Use this when:

- You want to ask broad questions that span multiple parts of the library (e.g. "how do functions, relations and the optimizers fit together?").
- You are working in a chat interface where you paste context manually.
- You want a self-contained snapshot that doesn't require the LLM to make additional requests.

The drawback is size: even without the Theory Guide, it is a large file, mostly due to the API reference and the code of the user guide, and it might consume a considerable portion of your model's context window.

## Option 3: Per-page Markdown

Every page in this documentation has a Markdown twin at the same URL with `.md` appended (e.g. `api.html.md`). Use this when:

- Your question is about a specific class, concept or feature and a single page covers it.
- You want to keep context usage minimal.
- You are building a retrieval pipeline and want to index individual pages rather than the full bundle.
- You need a page that is left out of the bundles, like the Theory Guide.

The easiest way to get the Markdown for the page you are currently reading is the **Download Markdown** link in the right sidebar of every page, below **Edit on GitHub** and **Show Source**.
